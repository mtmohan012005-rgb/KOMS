1. EXECUTIVE SYSTEM ARCHITECTURE OVERVIEW
--------------------------------------------------------------------------------
The Karate Organization Management System (KOMS) is a multi-tier, enterprise-grade
martial arts organization platform designed for dojo networks, instructors, and
practitioners. The ecosystem consists of three primary layers:

  [ Android Client Tier ]        [ Web Frontend Tier ]
   - Native Kotlin (MVVM)         - Responsive HTML5 / CSS3 / ES6+
   - Hybrid WebView APK           - Bootstrap 5 & Custom Martial Dark Theme
              \                         /
               \                       /
                v                     v
          +--------------------------------------+
          |       Apache HTTP Web Server         |
          |       PHP 8.2 Engine Runtime         |
          +--------------------------------------+
                             |
                   [ Application Layer ]
            - Session-based Web Portals (Admin/Master/Senior/Student)
            - RESTful JSON API Services (/api/)
            - Security Middleware (CSRF, RBAC, BCrypt, Audit Logs)
                             |
                    [ Persistence Tier ]
            - Primary: Aiven Cloud Managed MySQL 8.0 (SSL Encrypted)
            - Fallback: High-Availability MariaDB 10.x inside Container

    - tournaments, tournament_registrations, tournament_brackets: Matches, brackets, medals.
    - announcements: Targeted broadcast announcements by dojo or organization.
    - audit_logs: Comprehensive security audit trail logging every user login & mutation.
    - koms_system_flags: Idempotent migration and initialization flag tracker.

6. RENDER CLOUD HOSTING & DEPLOYMENT PROCESS
--------------------------------------------------------------------------------
The backend is deployed as a fully containerized Docker service on Render Cloud.

  * Render Specifications:
    - Service Type: Web Service (Docker Runtime)
    - Service Name: koms-backend
    - Region: Singapore (ap-southeast-1)
    - Plan: Free Tier
    - Auto-Deploy: Enabled (Triggered automatically on git push to 'main' branch)
    - Public Endpoint: https://koms-backend.onrender.com
    - Blueprint Configuration: render.yaml (Infrastructure as Code)

  * Step-by-Step Render Deployment Pipeline:

    STEP 1: GIT PUSH TRIGGER
      Developer pushes commits to 'main' on https://github.com/mtmohan012005-rgb/KOMS.git.
      Render's GitHub Webhook detects the new commit SHA and triggers a build.

    STEP 2: DOCKER IMAGE BUILD
      Render pulls the repository and builds the image using './Dockerfile':
        - Pulls base image 'php:8.2-apache'.
        - Installs OS dependencies: mariadb-server, mariadb-client, libpng, libjpeg, libfreetype.
        - Compiles PHP extensions: gd, mysqli, pdo, pdo_mysql, opcache.
        - Enables Apache modules: rewrite, headers.
        - Copies Apache configuration files and PHP production optimization settings.
        - Copies application source code to '/var/www/html'.
        - Installs and makes executable '/usr/local/bin/docker-entrypoint.sh'.
        - Sets file ownership to 'www-data:www-data' with secure permissions (chmod 755 / 775).

    STEP 3: CONTAINER PROVISIONING & STARTUP
      Render starts the Docker container and executes 'docker-entrypoint.sh':
        1. Port Reconfiguration:
           Dynamically reads Render's assigned '$PORT' (e.g., 10000) and rewrites Apache's
           'ports.conf' and '000-default.conf' using sed.
        2. Database Discovery & Health Probing:
           Reads environment variables (DB_HOST, DB_USER, DB_PASSWORD, DB_PORT, DB_NAME).
           Executes 'mysqladmin ping' with SSL options (--ssl=1 --ssl-verify-server-cert=0).
        3. Schema Verification & Auto-Migration:
           If tables do not exist in the database, the entrypoint automatically executes:
           mysql "$DB_NAME" < /var/www/html/database/schema.sql
        4. High-Availability Fallback:
           If the external database is unreachable, the entrypoint automatically initializes
           and starts an embedded local MariaDB daemon (/usr/sbin/mariadbd) inside the
           container, creating the database and importing schema.sql on the fly.
        5. Idempotent Data Cleanup:
           Executes 'cleanup_legacy_demo_accounts', ensuring demo data integrity and setting
           the 'legacy_demo_accounts_removed_v1' flag in 'koms_system_flags'.
        6. Web Server Execution:
           Hands off process execution to 'exec apache2-foreground'.

    STEP 4: HEALTH CHECK & TRAFFIC ROUTING
      Render polls the health check endpoint:
        GET https://koms-backend.onrender.com/api/index.php
      Once the endpoint returns HTTP 200 OK, Render switches traffic to the new container
      with zero-downtime deployment, terminating SSL via Cloudflare CDN.

8. SECURITY, AUTHENTICATION & ACCESS CONTROL
--------------------------------------------------------------------------------
  * Authentication:
    - Passwords hashed using PHP's native password_hash() with BCrypt (Cost factor 10).
    - Session regeneration (session_regenerate_id(true)) upon login to prevent fixation.
    - Unified login accepting either Email Address or alphanumeric Member ID.

  * Role-Based Access Control (RBAC):
    - Strict role enforcement via middleware require_role($role).
    - Unauthorized access triggers audit logging and redirects to appropriate portal.
    - Valid roles: 'super_admin', 'master', 'senior', 'student'.

  * Cross-Site Request Forgery (CSRF):
    - Cryptographically secure CSRF token generated per session (bin2hex(random_bytes(32))).
    - Mandatory token validation on all state-changing HTTP POST operations.

  * Data Sanitization & SQL Injection Prevention:
    - 100% of dynamic database queries utilize PDO prepared statements with parameter binding.
    - Strict input sanitization via htmlspecialchars() and trim().

  * Enterprise Audit Trail:
    - Dedicated audit_logs table logging every login, role transition, dojo registration,
      and financial mutation with user ID, IP address, and timestamp.
